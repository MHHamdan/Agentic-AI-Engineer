## What "done" looks like at beginner tier

Per the [`projects/README.md`](../README.md) tier framing, beginner-tier projects produce:

- **A working CLI or minimal-UI build** — runnable end-to-end, with setup instructions a stranger can follow
- **Three example outputs** — committed to the repo as concrete demonstrations
- **A short write-up** (~500 words) reflecting on architecture choices and surprises
- **Submission to `docs/community/showcase.md`** — your work gets highlighted in the community rotation

Beginner tier doesn't require: production deployment, custom evaluation harness, multi-agent topology, advanced observability. Those are the intermediate and capstone tiers' surface.

## Picking a project

Both beginner projects exercise Path 01's foundations:

- **#01 (Personal research assistant)** — multi-step agent loop with web search + fetch + synthesis tools. The "I built an agent that does something useful" portfolio piece.
- **#02 (PDF Q&A bot)** — chunked PDF ingestion + retrieval + citation-grounded answers. The canonical RAG starter; useful if Path 02 is your next path.

Pick the one whose deliverable you'd actually want to use. The dogfooding loop is what makes a small project finishable.

## Submission

When you finish, the `docs/community/showcase.md` submission lists your repo + a one-paragraph description + a screenshot. Beginner-tier submissions show up in the README rotation; the project README links to the showcase entry so future learners can see what others built from this brief.
